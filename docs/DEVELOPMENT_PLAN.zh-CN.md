# Yes Steve Attribute 开发计划

本文件定义从配置模板到首个可用版本的开发顺序。当前阶段只建立配置契约和测试样例，不开始实现 Java 功能。

## 阶段 0：配置契约确认（当前阶段）

1. 确认配置目录、命名空间、中文名称与稳定 ID 的规则。
2. 确认 `ProgressionState`、`SourceDomain`、`AttributeContribution`、`DamageRequest` 和 UI DTO 的字段。
3. 确认公式语法、单位、分段公式、随机数范围和错误处理策略。
4. 确认装备、饰品、圣遗物、声骸、Buff 的实例保存策略。
5. 确认配置模板中的测试期望值。

此阶段完成后等待作者确认。确认前不开始实现属性、公式或战斗代码。

## 阶段 1：共享模型与配置加载

1. 创建纯 Java 的共享模块，不依赖 Forge 或 Paper。
2. 实现命名空间 ID、中文别名、单位、版本号和配置来源优先级。
3. 实现 YAML → 内部模型的加载器和 Codec 校验。
4. 实现 UTF-8、Unicode NFC、中文文件名和错误定位。
5. 实现 reload、缓存失效和“保留上一份有效配置”的失败策略。

交付物：能够加载模板并输出校验报告，但还不接入 Minecraft 实体。

## 阶段 2：ProgressionState 与属性快照

1. 实现经验、等级、职业、升阶和解锁条件。
2. 实现属性定义、来源树、单位和聚合阶段。
3. 实现可注册的 `SourceDomain`。
4. 实现默认来源域：等级成长、基础属性、装备、饰品、圣遗物、声骸、Buff。
5. 实现属性依赖图、派生属性和 trace。

交付物：离线测试可以根据一个角色、装备和 Buff 生成完整 `AttributeSnapshot`。

## 阶段 3：公式引擎

1. 先实现声明式表达式、分段条件、`min/max/clamp/pow` 等内置函数。
2. 实现统一短变量上下文：`<lvl>`、`<属性名>`、`<目标.属性名>`、`<技能.参数>` 和确定性随机函数。
3. 加入未知属性、循环依赖、单位错误、NaN、Infinity、超时和结果范围检查。
4. 实现单一的内联表达式执行器；内部可以使用受限 JavaScript 引擎，但作者始终只写这一种表达式语法。
5. 实现公式样例输入、结果和依赖 trace。

交付物：模板中的所有公式可以离线验算，并能报告错误位置。

## 阶段 4：装备与来源域实例

1. 实现 `live`、`frozen`、`migration` 三种实例策略。
2. Forge 使用 Data Components/custom data 保存身份；Paper 使用 PersistentDataContainer。
3. 实现外部 Mod 物品 adapter。
4. 实现装备、饰品、圣遗物、声骸的槽位、容量、套装、成本、词缀和强化。
5. 实现 reload 后的缓存失效，不自动改写背包中的冻结实例。

交付物：同一件实例在 Forge 集成服务器和 Paper 端都能生成一致的来源贡献。

## 阶段 5：战斗管线与原版伤害入口

1. 实现 `DamageRequest`、`DamagePacket` 和统一攻击 RNG。
2. 实现物理、元素、抗性、穿透、护甲和护盾的基础流程。
3. 实现通用 Proc：普通暴击、元素暴击、破防、触发效果和冷却。
4. 保证一次命中最终只调用一次原版 `hurt`/伤害事件入口。
5. 发布战斗事件和 trace，支持离线回放。

交付物：模板中的普通攻击、火焰暴击和抗性测试通过。

## 阶段 6：YSS/YSM/VFX/Camera 接入

1. 将 YSS 命中段从直接伤害数字改为 `damage_profile` 引用。
2. 服务端根据技能和命中段重新解析伤害，不信任客户端伤害值。
3. YSM 负责模型和动画，VFX/Camera 消费统一战斗事件。
4. 增加攻击开始、命中、暴击、硬直、元素反应和攻击结束事件。

5. 增加 MythicMobs 适配器：让 MythicMobs 负责技能触发、目标选择、条件和时序，YSA 负责属性读取、公式、Proc 和最终伤害。
6. 提供 `ysa-damage`、`ysa-buff`、`ysa-attribute` 等 MythicMobs 技能机制，以及 `<caster.ysa.属性名>`、`<target.ysa.属性名>` 占位符。

## 阶段 7：UI API 与适配器

1. 实现平台无关的 `ysa-ui-api`。
2. 实现属性快照、来源解释、构筑预览、验证和战斗事件订阅。
3. 实现 MineBrowse 适配器。
4. 实现 Paper 端 DragonCore 适配器，接入现有统一 UI 系统。
5. 保证 UI 只能读取快照或发起经过校验的请求，不能成为战斗权威。

## 阶段 8：Paper 插件与兼容性测试

1. 接入 Paper 实体、事件、存档和网络层。
2. 接入 MythicMobs 的实体等级、技能组、条件、目标选择器和伤害事件。
3. 运行与 Forge 集成服务器相同的配置和离线测试。
4. 测试旧物品、外部 Mod 物品、配置 reload、玩家重连和跨版本迁移。
5. 发布第一版配置格式和迁移指南。

## 阶段完成门槛

- 阶段 0：作者确认配置模板。
- 阶段 1～3：离线配置与公式测试全部通过。
- 阶段 4：实例策略和存档格式确认。
- 阶段 5：原版伤害、无敌帧、护甲和盾牌测试通过。
- 阶段 6～7：YSS 和 UI 适配器通过集成测试。
- 阶段 8：Paper 端与 Forge 集成服务器的结果一致。
