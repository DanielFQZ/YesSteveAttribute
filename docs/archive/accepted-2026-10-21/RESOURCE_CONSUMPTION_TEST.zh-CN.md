# 当前验收：资源原子消耗

本轮只需验收资源扣费和反馈，上轮 YSS 伤害联动已通过并归档。完全退出并重启客户端加载新的 YSA jar；YSS jar 和技能配置无需变更。

使用有管理员权限的测试世界。下面以示例模板的“充能”为主：它默认不恢复、不衰减，便于准确读数。若你调整过这些公式，以聊天显示的本次前后值为准。

## 1. 预览不扣费，成功扣费直接反馈

```text
/ysadebug on
/ysa resource @s "充能" set 30
/ysa consume @s "充能" 10 preview
/ysa resource @s "充能"
```

应提示“可支付（仅预览，未扣除）”，预计 30 → 20，但查询和 HUD 仍为 30。

```text
/ysa resource @s "充能" consume 10
```

应提示“扣除成功”，30 → 20，HUD 充能值随即变为 20。退出世界再进入，充能应保留 20（模板无恢复/衰减时）。

## 2. 余额不足时整笔不扣

```text
/ysa consume @s "充能" 21 "精力" 20
```

应提示“余额不足，整笔未扣除”，充能缺少 1，仍为 20；精力也不扣。精力本身每秒恢复 40，请以聊天显示的同次操作前后值相等为准，避免将正常恢复误判为扣费异常。

```text
/ysa consume @s "充能" 5 "精力" 20
```

两项余额足够时，充能应 20 → 15，精力同时减少 20；若精力不足，仍是两项都不扣。

## 3. 恰好足额与非法请求

```text
/ysa resource @s "充能" consume 15
/ysa resource @s "充能" consume 1
/ysa consume @s "充能" 1 "充能" 2
/ysa consume @s "充能" 0 "不存在" 0
```

依次应为：成功扣到 0；余额不足且不扣；重复资源报错；未知资源报错。错误均应在聊天中可见，不用翻日志。
