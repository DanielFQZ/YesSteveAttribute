# 当前验收：YSS 技能起手资源消耗

2026-10-21：自动化验证完成后交付本轮。资源原子扣费和 YSS 伤害阶段已通过，不必重做历史测试。本轮验证实际动画起手到支付、效果许可的完整客户端流程。

## 1. 重启并配置一个动作

完全退出并重启拍摄端加载新版 YSS。YSS 网络协议已升级为 2，联机时服务器和所有客户端须安装同一新版 YSS；服务器还需此前已验收的 YSA 资源接口版本。

先备份自己的 hit.json。在命中编辑器中选择一个容易单独触发的攻击动画（例如 `attack_1`），在动画级“起手资源消耗”填写：

```text
充能=10
```

该字段在“Camera攻击辅助”下方，属于整个动画，不属于某个命中段。留空表示免费；多种资源写作 `充能=10;精力=20`，最多 8 项。保存并重新打开，确认费用、原来的伤害模式、VFX 碰撞盒和镜头配置都保留。

不要把测试费用同时填到所有连招动画；每次独立动画起手都收费，连招的多个动画会各自支付。旧动画未填写费用仍免费。

本地保存后服务器按文件时间/大小刷新；客户端未刷新时重进世界。多人服必须同步服务器 hit.json，客户端输入费用不会替代服务端费用。

## 2. 空挥也只扣一次

```text
/ysadebug on
/ysa resource @s "充能" set 30
```

面对空地，单独触发配置了费用的动画一次，不要一直按住攻击。预期充能 30 → 20。等动画结束，余额不应继续下降。再次单独播放应变为 10。

以上数字使用默认充能无恢复/衰减配置；若你改过公式，以本次起手的实际变化为准。主动取消已获准的动作也不退款。

## 3. 命中多个目标不会多扣

把充能重新设为 30。用同一动画一次命中两个测试目标，或让该动画内已有的多个段依次命中。

预期整个动作只扣 10，充能为 20；伤害继续按各段配置和原版无敌帧处理。不要用普通原版攻击或 `/ysa damage` 替代本步。

## 4. 不足时拒绝效果

```text
/ysa resource @s "充能" set 5
```

再次触发配置了 10 点费用的动画，预期聊天提示资源不足、缺口为 5，余额仍为 5。该次动作不产生 YSS 命中伤害、施法者位移或滞空；若有根运动，本地实体也不应由该动作推进。

YSM 动画和已发出的特效/镜头可能仍播放：当前事件发生在动画起手之后，本轮阻止的是 YSS 技能效果，不会强制撤销第三方动画/特效。拒绝后保留该次动画的原版攻击抑制，防止落回普通攻击。

把充能补到 30，再重新触发一次，应恢复效果并只扣 10。同一次已拒绝动作不会因为中途补充资源自动恢复。

## 5. 多资源与免费兼容

可将费用改为 `充能=10;精力=20`，保存后以充能 5 起手，应整笔不扣，精力不因该动作扣除（精力正常每秒恢复仍继续）。补足两种余额，再次起手才同时支付。

清空费用并保存，充能 0 时动作应仍可命中。无费用的其他动画应保持可用。非法输入如 `充能=-1` 或 `充能=1;充能=2` 应阻止保存并提示。

## 本轮边界

- 每次动画重播或循环回卷视为新动作，分别收费。一次动作最多授权 1200 个服务器 tick（约 60 秒）；长期持续技能不属于本轮设计。
- 收费动作需先等服务器应答才开始判定和移动，动画本身继续计时；极短窗口或高延迟时可能错过早期命中/位移，不会补算已经过去的窗口。
- 正常动画结束前已登记的延迟命中仍可落地，使用登记时的段配置且不再扣费；死亡、打断、关闭攻击模式、切模型或换维度会清理待执行命中。取消和伤害被挡均不退款。
- 本轮自动测试覆盖服务端支付/授权/执行器和网络包编解码；UI、真实动画时机、联机延迟与特效仍以本次实测为准。完整服务端动画真实性、所有命中窗口与客户端几何复核尚未实现。

回报空挥、多目标、余额不足三种情况下的充能变化，以及不足时目标是否扣血即可。
