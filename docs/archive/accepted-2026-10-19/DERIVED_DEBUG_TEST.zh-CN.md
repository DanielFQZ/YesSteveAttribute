# 派生属性、战斗试算与实时调试面板验收

完全退出并重启客户端加载新 jar；`/ysa reload` 不能热更新 Java 代码。多人测试须同时更新服务器和客户端，属性同步协议已升级为 2。

## 实时调试面板

```text
/ysadebug on
/ysadebug off
```

不带参数的 `/ysadebug` 为切换开关。右侧半透明面板按配置顺序列出所有属性，包括 `visible: false` 字段、资源、派生值和元素亲和。空间足够时分栏展示全部；放不下时标题显示页码：

```text
/ysadebug next
/ysadebug prev
/ysadebug page 2
/ysadebug scale 0.75
```

缩放范围 0.5～1.5，默认 0.75。F1 时隐藏，退出服务器后自动关闭。检查不同窗口尺寸和 GUI 缩放下是否遮挡、溢出或字太小。面板不创建原版计分板目标，和原版侧边计分板同时开启时可能重叠。

```text
/ysa resource @s "精力" set 0
```

应在面板直接看到精力值每秒增加 40，变化值短暂显示绿色，最高 500，无需反复执行查询命令。等待时间以未暂停的服务器运行时间为准。角色修改、reload、装备变化会自动更新；装备检查间隔为 20 个服务器 tick。显示最多四位小数，实际计算和同步仍保留 double 精度。

## 派生值与公式输出的装备加成

清空双手、卸下带 YSA 加成的装备：

```text
/ysa role @s "示例战士" 1
/ysa attr @s "基础伤害"
/ysa attr @s "生命上限"
/ysmclient molang execute ysa.attr('基础伤害')
```

默认模板应为：力量 10.6、基础伤害 69.96、生命上限 240.64、法力上限 32.76。生命上限目前仅为计算属性，红心不随之改变。命令、调试面板和 Molang 数值一致（Molang 为 float，允许微小舍入差异）。

```text
/give @s minecraft:stick{YSAAttributes:["力量: 10","基础伤害: 5","法力上限: 20","炽炎: 30"]} 1
```

持有并等待约 1 秒：力量 20.6，基础伤害 `(20.6 × 6.6) + 5 = 140.96`，法力上限 52.76，元素亲和“炽炎”。`/ysa attr @s "基础伤害"` 展示公式贡献 135.96 和装备贡献 5；无属性伤害约 84.576、炽炎伤害约 56.384。卸下后恢复，反复 reload 不累计。增大法力上限保留已有余额，减少时截断。

资源 current 字段及 `本次是否暴击` 等 combat_input 仍不可由装备写入。

## 战斗试算

清空带 YSA 加成的装备，保留示例战士 1 级：

```text
/ysa combat @s @s
/ysa combat @s @s 2
```

只试算、不扣血。允许自己作为目标方便单人测试。默认倍率 1、随机值 0.5，首条最终伤害 69.96，第二条 139.92（默认护甲/暴击均为 0）。聊天依次列出基础伤害、元素分配、减伤、暴击概率及最终值。

```text
/give @s minecraft:stick{YSAAttributes:["暴击: 10","暴击抗性: 10","护甲: 20"]} 1
```

持有、等待刷新后：

```text
/ysa combat @s @s 1 0.25
/ysa combat @s @s 1 0.75
```

暴击概率应为 0.5，护甲减伤 5，暴击前伤害 64.96。第一条暴击，最终 97.44；第二条不暴击，最终 64.96。随机值必须在 [0, 1)，实际判定为 `随机值 < 暴击概率`。

试算结果不写回常驻玩家属性。依赖目标、`本次是否暴击` 或经验上下文的字段，在面板和 `/ysa attr` 中标为“待战斗”；Molang 对没有数值快照的字段仍返回 0。公式负的最终结果在试算中原样显示，不触发治疗。YSS 命中与原版扣血留到下一阶段联调。

## 错误回滚与回归

备份 `formulas.yml`，把基础伤害临时改为 `"1 / 0"` 后 `/ysa reload`：应失败并保留旧面板、资源与配置。恢复文件并 reload。条件表达式和 `&&/||` 已支持短路，`1 ? 10 : 1 / 0` 应得到 10；语法错误和循环依赖仍拒绝。

普通派生公式可以依赖资源余额；资源参数不允许依赖 current 或战斗事件，即使该依赖位于未执行分支。若资源 tick 后的余额导致派生公式出错，保留本次更新前的余额和快照、聊天提示一次，修正公式后恢复。

检查重进世界、死亡/重生和跨维度后的快照；多人观察者应收到对应玩家的数值。实际 HUD 外观、指令开关、tick 与多人联动尚需实机验收；自动测试覆盖公式/战斗计算、数据包往返、显示精度及分页完整性。
